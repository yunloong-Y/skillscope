# 日志分析六步法 · 细则

1. **结论先行**：一句话说清核心发现或根因，不绕弯、不铺垫。
2. **分阶段时间轴**：按阶段一/二/三还原，每阶段给出关键时间戳、事件、原始 message。
3. **完整指令清单**：逐项列出所有相关指令，保留原始字节、状态、reason、victim 等字段。
4. **原始数据全量**：能列全量就列全量（如 73 次电量读数、41 个文件清单），异常项高亮，用 HTML 报告导出。
5. **可留存报告**：阶段划分、去重时间轴、根因提示都要进 HTML 文件。
6. **根因 + 下一步**：给出具体排查方向（某个 BLE cmd、眼镜端日志、后端查询），并询问是否需要整理成排查单。

## 硬要求

- 真实计算时长、差值、字节含义，不凭猜测下结论。
- 两份日志内容一致时先说明，避免重复劳动。
- 未做的推断要明确写「未做任何推断」，不替用户补关系。
